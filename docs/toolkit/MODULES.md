# Модули Mac Bootstrap Toolkit

## Назначение

Mac Bootstrap Toolkit построен по модульному принципу.

Каждый модуль отвечает за отдельную область ответственности,
а общие механизмы выносятся в Core.

Модульная архитектура позволяет добавлять новые возможности
без переписывания существующих компонентов.

Каждый модуль должен по возможности проходить общий жизненный цикл:

```text
Check
  ↓
Apply
  ↓
Verify
````

Для безопасного предварительного выполнения Bootstrap
предусматривается Dry-run:

```text
Check
  ↓
Planned Changes
```

# Структура

```text
modules/

├── core/
├── discovery/
├── bootstrap/
├── apps/
├── settings/
└── vscode/
```

В перспективе к этим уровням добавляются:

```text
Blueprint
Verification
Restore
AI Assistant
```

---

# Core

**Core** — фундамент Toolkit.

Содержит общие сервисы, которыми пользуются остальные компоненты.

Основные области:

* Common — общие функции;
* Logger — единый вывод и история запусков;
* Preflight — проверка готовности системы;
* Homebrew — работа с Homebrew;
* Git — работа с Git;
* SSH — подготовка SSH;
* Terminal — подготовка терминального окружения;
* Configuration — общие механизмы работы с конфигурацией.

Core не должен содержать логику конкретного пользовательского
окружения.

---

# Discovery

**Discovery Engine** отвечает за анализ текущего Mac.

Он определяет фактическое состояние рабочего окружения и передаёт
результаты в `config/generated/`.

Основные области:

* Applications;
* Homebrew;
* Git;
* VS Code;
* macOS Settings;
* Workspace;
* другие компоненты окружения.

Discovery только анализирует систему и не изменяет её состояние.

Результаты Discovery сохраняются в Generated Configuration
и используются последующими этапами Toolkit.

---

# Bootstrap

**Bootstrap Engine** отвечает за применение целевого состояния.

Основные области:

### Core

* Homebrew;
* Git;
* SSH;
* Terminal.

### Applications

* Homebrew Packages;
* Homebrew Casks;
* App Store.

### VS Code

* Extensions;
* Settings;
* Projects;
* Workspaces;
* другие пользовательские данные.

### macOS

* Finder;
* Dock;
* Keyboard;
* Trackpad;
* Screenshots;
* другие системные настройки.

### Workspace

* folders;
* Git repositories;
* remotes;
* branches;
* VS Code Projects;
* VS Code Workspaces.

Не все перечисленные компоненты реализованы на текущем этапе.
Их целевой состав определяется архитектурой и `ROADMAP.md`.

Основной принцип Bootstrap:

```text
Check
  ↓
Apply
  ↓
Verify
```

Bootstrap должен быть идемпотентным.

Повторный запуск уже настроенного компонента не должен
без необходимости изменять его состояние.

---

# Dry-run

**Dry-run** — безопасный режим предварительного выполнения Bootstrap.

Он не является отдельным Engine или самостоятельной областью
ответственности.

Dry-run использует существующие Bootstrap-модули и их проверки,
но вместо фактического применения изменений формирует
описание предполагаемых действий.

Основной принцип:

```text
Current State
      ↓
Bootstrap Check
      ↓
Planned Changes
```

Dry-run должен:

* выполнять проверки текущего состояния;
* определять, какие компоненты требуют изменений;
* показывать предполагаемые действия;
* использовать общий Logger;
* формировать понятный Summary;
* не изменять состояние системы.

Таким образом:

```text
Bootstrap
    ↓
Check
    ↓
Apply
    ↓
Verify
```

а в Dry-run:

```text
Bootstrap
    ↓
Check
    ↓
Planned Changes
```

Dry-run предназначен для безопасной проверки того,
что Toolkit собирается сделать, до фактического применения изменений.

Он не заменяет Bootstrap и не создаёт отдельную конфигурацию.

---

# Applications

Модули `apps/` отвечают за установку приложений.

Основные источники:

* Homebrew Packages;
* Homebrew Casks;
* App Store.

Discovery определяет текущее состояние приложений,
а Bootstrap использует эти данные для восстановления.

В дальнейшем Blueprint будет определять, какие приложения
действительно входят в целевой профиль.

---

# macOS Settings

Модули `settings/` отвечают за системные настройки macOS.

Каждая область настройки может иметь отдельный модуль.

Текущие области:

* Finder;
* Dock;
* Keyboard;
* Trackpad;
* Screenshots.

Общий принцип:

```text
Discovery
    ↓
Generated Configuration
    ↓
Settings Module
    ↓
macOS
```

Новые настройки должны по возможности использовать общие механизмы,
а не дублировать одинаковую логику.

---

# VS Code

Модули `vscode/` отвечают за рабочее окружение VS Code.

Целевая область включает:

* Extensions;
* Settings;
* Projects;
* Workspaces;
* Keybindings;
* Snippets;
* Profiles.

Компоненты добавляются по мере развития Bootstrap Engine.

---

# Workspace

Workspace отвечает за рабочее пространство пользователя.

Включает:

* директории;
* Git repositories;
* remotes;
* branches;
* VS Code Projects;
* VS Code Workspaces.

Workspace проходит общий жизненный цикл:

```text
Discovery
    ↓
Generated Configuration
    ↓
Blueprint
    ↓
Verification
    ↓
Bootstrap / Restore
```

---

# Blueprint

**Blueprint Engine** определяет целевой состав рабочего окружения.

Он будет отвечать за:

* выбор компонентов;
* формирование целевого профиля;
* исключение ненужных компонентов;
* изменение обнаруженных параметров;
* формирование переносимого Blueprint.

Blueprint отделяет:

```text
что обнаружено
```

от:

```text
что необходимо восстановить
```

---

# Verification

**Verification Engine** проверяет соответствие системы
целевому состоянию.

Он определяет:

* что уже настроено;
* что отличается;
* что отсутствует;
* что требует изменения.

Verification не изменяет систему.

---

# Restore

**Restore Engine** отвечает за полное воспроизводимое восстановление
рабочего окружения.

Он объединяет результаты Blueprint, Verification и Bootstrap
и учитывает зависимости между компонентами.

---

# AI Assistant

**AI Assistant** является дополнительным уровнем автоматизации.

Он не заменяет существующие модули, а работает поверх них.

Основные направления:

* анализ окружения;
* рекомендации;
* создание Blueprint;
* объяснение различий;
* диагностика;
* помощь при восстановлении;
* автоматическое разрешение конфликтов.

---

# Правила модульной архитектуры

Каждый модуль должен:

* иметь одну основную область ответственности;
* использовать общие Core-механизмы;
* не дублировать логику других модулей;
* быть максимально независимым;
* поддерживать идемпотентный запуск;
* отделять проверку от применения изменений;
* использовать единый Logging System;
* возвращать предсказуемый результат выполнения.

Основной жизненный цикл модуля:

```text
Check
  ↓
Apply
  ↓
Verify
```

Для безопасного предварительного выполнения:

```text
Check
  ↓
Dry-run
  ↓
Planned Changes
```

Добавление нового компонента должно по возможности следовать
общему архитектурному жизненному циклу:

```text
Discovery
    ↓
Generated Configuration
    ↓
Blueprint
    ↓
Verification
    ↓
Bootstrap
    ↓
Restore
```

При этом не каждый компонент обязан сразу реализовывать
все этапы жизненного цикла.

# Статус реализации

`MODULES.md` описывает **целевую структуру модульной системы**.

Текущий статус отдельных модулей определяется в:

* `ROADMAP.md` — план развития;
* `TODO.md` — ближайшие задачи;
* `CHANGELOG.md` — история изменений.

Dry-run является следующим функциональным режимом
для безопасного предварительного выполнения Bootstrap
и не требует отдельного архитектурного уровня.

Поэтому появление нового модуля или режима не требует перестройки
этого документа — достаточно реализовать соответствующий
архитектурный блок и обновить его статус в Roadmap.
