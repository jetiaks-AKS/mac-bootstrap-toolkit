# Конфигурация Mac Bootstrap Toolkit

## Назначение

Mac Bootstrap Toolkit использует конфигурационные файлы для хранения параметров, необходимых Discovery Engine и Bootstrap Engine.

На текущий момент проект использует два типа конфигурации:

- базовую конфигурацию Toolkit;
- автоматически сгенерированную конфигурацию Discovery.

Это позволяет постепенно перейти от ручной настройки Bootstrap к полностью автоматическому восстановлению рабочего окружения.

---

# Принцип работы

На текущем этапе развития Toolkit используются два источника конфигурации.

```
                    Bootstrap
                   ↗          ↖
                  │            │
           config/      config/generated/
                              ▲
                              │
                         Discovery
```

Базовая конфигурация входит в состав проекта и используется Bootstrap Engine.

Автоматически сгенерированная конфигурация создаётся Discovery Engine на основе анализа текущей системы пользователя.

Bootstrap постепенно переводится на использование автоматически сгенерированной конфигурации.

## Базовая конфигурация

Файлы, расположенные непосредственно в каталоге `config/`, являются базовой конфигурацией Toolkit.

Они входят в состав проекта и используются Bootstrap Engine.

При необходимости пользователь может изменить их вручную.

---

## Автоматически сгенерированная конфигурация

Каталог `config/generated/` содержит конфигурационные файлы, автоматически сформированные Discovery Engine.

Они отражают текущее состояние системы пользователя и используются Bootstrap Engine.

Каждый запуск Discovery может полностью пересоздать содержимое каталога `generated/`.

---

# Формат конфигурации

Все конфигурационные файлы Toolkit используют единый формат.

Пример:

```ini
[mac-bootstrap-toolkit]

PATH="/Users/user/Projects/mac-bootstrap-toolkit"
REMOTE="git@github.com:user/mac-bootstrap-toolkit.git"
CURRENT_BRANCH="main"
```

Каждая секция описывает один объект.

Все параметры внутри секции представлены в формате:

```
KEY="VALUE"
```

---

# Config Engine

Для чтения конфигурационных файлов используется Config Engine.

На текущий момент реализованы следующие функции:

- `config_sections()`
- `config_get()`

Все новые Bootstrap-модули используют Config Engine и не содержат собственной логики разбора конфигурационных файлов.

---

# Принципы

Подсистема конфигурации построена на следующих принципах:

- единый формат всех конфигурационных файлов;
- простое текстовое представление;
- разделение Discovery и Bootstrap;
- отсутствие дублирования логики чтения конфигурации;
- единый API через Config Engine;
- модульность;
- идемпотентность.
