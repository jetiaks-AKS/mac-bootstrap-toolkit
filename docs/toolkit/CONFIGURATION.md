# Конфигурация Mac Bootstrap Toolkit

## Назначение

Конфигурационная система Toolkit отделяет данные рабочего окружения
от логики его обработки.

Она связывает основные этапы системы:

```text
Current Mac
    ↓
Discovery
    ↓
Generated Configuration
    ↓
Blueprint
    ↓
Verification / Bootstrap / Restore
````

---

# Два состояния конфигурации

Toolkit разделяет фактическое и целевое состояние.

### Observed State

Состояние, обнаруженное на текущем Mac.

Оно формируется Discovery и сохраняется в:

```text
config/generated/
```

### Desired State

Состояние, которое должно быть получено на целевом Mac.

Оно определяется Blueprint.

```text
Observed State
      ↓
   Blueprint
      ↓
Desired State
```

Такое разделение позволяет сохранить существующее окружение
как основу, но независимо определить, что именно необходимо
восстановить.

---

# Generated Configuration

`config/generated/` — основной результат работы Discovery.

Здесь хранится автоматически сформированное описание
обнаруженного рабочего окружения.

Каталог может содержать конфигурации для:

* приложений;
* Git;
* Workspace;
* VS Code;
* macOS Settings;
* других компонентов Toolkit.

Структура каталога может расширяться вместе с развитием проекта.

Generated Configuration не должна требовать ручного дублирования
пользовательских настроек в Bootstrap-коде.

---

# Статическая конфигурация Toolkit

Каталог `config/` используется для настроек самого Toolkit
и других данных, которые не являются результатом Discovery.

Таким образом:

```text
config/
    → конфигурация самого Toolkit

config/generated/
    → обнаруженное состояние рабочего окружения
```

Эти два типа конфигурации не должны смешиваться.

---

# Blueprint

Generated Configuration описывает:

> **что есть сейчас.**

Blueprint определяет:

> **что должно быть.**

Blueprint может использовать результаты Discovery как основу,
но позволяет независимо определить целевой профиль:

* какие компоненты нужны;
* какие параметры необходимо сохранить;
* какие параметры изменить;
* какие компоненты исключить;
* какие компоненты являются обязательными.

Blueprint является источником Desired State для последующих
Verification, Bootstrap и Restore.

---

# Конфигурация и модули

Конфигурация содержит **данные**.

Модули содержат **логику работы с этими данными**.

Поэтому пользовательская настройка не должна без необходимости
дублироваться внутри кода.

Например, если Discovery определил размер Dock, Bootstrap должен
получать это значение из конфигурации, а не содержать собственное
фиксированное значение.

Это позволяет изменять настройки рабочего окружения без
редактирования логики Bootstrap.

---

# Форматы

Toolkit не требует единого формата для всех конфигураций.

Формат выбирается в зависимости от типа данных.

Могут использоваться:

* простые конфигурационные файлы;
* структурированные `.conf`;
* JSON;
* специализированные форматы для отдельных подсистем.

При этом формат не должен влиять на общую архитектуру:

```text
Discovery
    ↓
Configuration
    ↓
Blueprint
    ↓
Verification / Bootstrap / Restore
```

---

# Основные принципы

Конфигурационная система должна обеспечивать:

* разделение данных и логики;
* разделение Observed State и Desired State;
* отсутствие ненужного дублирования;
* воспроизводимость;
* расширяемость;
* совместимость между Discovery и Bootstrap;
* возможность добавления новых компонентов без изменения
  существующей архитектуры.

---

# Архитектурное правило

> **Configuration describes the environment.
> Modules define how to work with it.**

Изменение пользовательской настройки по возможности должно
осуществляться через конфигурацию, а не через изменение
Bootstrap-кода.

При добавлении нового компонента его конфигурация должна
встраиваться в общий цикл:

```text
Discovery
    ↓
Generated Configuration
    ↓
Blueprint
    ↓
Verification
    ↓
Bootstrap
    ↓
Restore
```
