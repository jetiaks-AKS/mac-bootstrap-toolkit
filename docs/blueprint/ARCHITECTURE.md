# Архитектурное решение №1

## Discovery не заменяет Bootstrap

Discovery не является отдельной системой восстановления.

Его задача — автоматически проанализировать существующее рабочее пространство пользователя и сформировать конфигурацию для существующего Mac Bootstrap Toolkit.

Bootstrap остаётся основным механизмом установки и настройки системы.

Discovery становится механизмом автоматического создания конфигурации.

Таким образом:

Старый Mac

↓

Discovery

↓

Автоматически создаёт Bootstrap Configuration

↓

Новый Mac

↓

Bootstrap

↓

Полностью восстанавливает рабочее пространство пользователя.

# Архитектурное решение №2

## Главное — рабочее пространство

Цель проекта — не восстановить компьютер.

Цель проекта — воспроизвести рабочее пространство пользователя.

Под рабочим пространством понимается:

- рабочие приложения;
- рабочие настройки;
- среда разработки;
- пользовательские рабочие каталоги.

Проект сознательно не пытается перенести всю систему.

Он переносит только то, что действительно необходимо пользователю для продолжения работы.

# Архитектурное решение №3

## Простота важнее количества функций

Каждая новая возможность должна отвечать на вопрос:

"Поможет ли она быстрее восстановить рабочее пространство пользователя?"

Если ответ отрицательный,
функция не должна добавляться в проект.

Mac Bootstrap Toolkit не стремится поддерживать все настройки macOS.

Поддерживаются только наиболее важные и востребованные настройки, влияющие на ежедневную работу пользователя.
