# Mac Blueprint

> Концепция развития Mac Bootstrap Toolkit.

> **Исторический документ.** Здесь зафиксирован ранний, впоследствии заменённый
> вариант дизайна Blueprint. Описанные ниже команды, этапы, профили, export и
> restore не являются контрактом текущей реализации. Актуальные архитектура и
> статус определены в [ARCHITECTURE.md](../toolkit/ARCHITECTURE.md) и
> [ROADMAP.md](../../ROADMAP.md), а текущее поведение Blueprint — в
> [CONFIGURATION.md](../toolkit/CONFIGURATION.md).

---

# Идея

Создать инструмент, который способен не просто настроить новый Mac,
а определить, из чего состоит идеальное рабочее окружение пользователя,
сохранить его в виде профиля и воспроизвести на любом новом Mac.

---

# Главная философия

Программа никогда не принимает решения за пользователя.

Её задача:

1. Проанализировать систему.
2. Показать найденные компоненты.
3. Позволить пользователю самостоятельно выбрать необходимые.
4. Создать Blueprint.
5. Восстановить выбранное рабочее окружение.

Toolkit помогает собрать Blueprint, но не пытается угадать,
что действительно важно пользователю.

Последнее решение всегда остаётся за человеком.

---

# Основные цели

- автоматически проанализировать систему;
- определить основные компоненты рабочего окружения;
- позволить пользователю выбрать, что сохранить;
- сформировать переносимый профиль;
- восстановить выбранные компоненты на новом Mac.

## Рабочее пространство

Не весь диск.

Только выбранные пользователем каталоги.

Например:

- Infrastructure
- Projects
- Templates
- Scripts
- Workspace

Большие пользовательские данные (Фото, Видео, Загрузки и т.п.)
умышленно не включаются.

# Возможные команды

```bash
bootstrap capture
```

Проанализировать текущий Mac и создать Blueprint.

---

```bash
bootstrap blueprint list
```

Показать сохранённые Blueprint.

---

```bash
bootstrap blueprint compare
```

Сравнить текущую систему с Blueprint.

---

```bash
bootstrap blueprint apply
```

Восстановить выбранный Blueprint.

---

# Основные принципы

- модульность;
- идемпотентность;
- Self-Healing;
- человекочитаемые файлы;
- управление версиями;
- воспроизводимость.

Blueprint не должен быть "умным".

Он не должен угадывать,
какие программы или каталоги являются важными.

Вместо этого Toolkit анализирует систему,
структурирует найденную информацию
и предоставляет её пользователю.

Пользователь самостоятельно принимает решение,
что станет частью Blueprint.

---

# Отличие от Time Machine

Mac Blueprint не является:

- резервной копией;
- заменой Time Machine;
- заменой Migration Assistant.

Его задача —
описать рабочее пространство пользователя,
а не сохранить весь компьютер.

# Главная идея

Не создавать резервную копию компьютера.

Создать описание идеального рабочего пространства пользователя.

Компьютер можно заменить.

Рабочее окружение должно оставаться неизменным.
