# Git Flow

Схема разработки проекта **Mac Bootstrap Toolkit**.

---

# Структура веток

Проект использует две основные ветки.

```
main
```

Содержит только стабильные версии проекта.

Каждый коммит в `main` соответствует проверенному релизу.

---

```
develop
```

Основная ветка разработки.

Все новые функции, исправления и рефакторинг выполняются здесь.

После завершения очередной версии изменения объединяются с `main`.

---

# Общая схема

```
                develop
                   │
        feat
                   │
        feat
                   │
        fix
                   │
        docs
                   │
        release
                   │
                   ▼
main  ───────── Merge ─────────► v1.1.0
                                  │
                                  Tag
```

После выпуска релиза разработка продолжается в `develop`.

---

# Ежедневная работа

Работа всегда начинается с ветки:

```bash
git checkout develop
```

Получить последние изменения:

```bash
git pull
```

После внесения изменений:

```bash
git add .

git commit -m "feat: ..."

git push origin develop
```

---

# Выпуск новой версии

После завершения разработки:

1. Обновить документацию.
2. Обновить номер версии.
3. Выполнить финальное тестирование.
4. Закоммитить изменения в `develop`.

---

# Перенос в main

Переключиться:

```bash
git checkout main
```

Выполнить Merge:

```bash
git merge --no-ff develop
```

Использование `--no-ff` позволяет сохранить историю разработки и явно отметить выпуск новой версии.

---

# Создание Git Tag

После успешного Merge:

```bash
git tag -a v1.1.0 -m "Mac Bootstrap Toolkit 1.1.0"
```

Отправить изменения:

```bash
git push origin main
git push origin --tags
```

---

# Возврат к разработке

После выпуска стабильной версии:

```bash
git checkout develop
```

Изменить номер версии:

```text
1.2.0-dev
```

Закоммитить:

```bash
git add .

git commit -m "chore: start development of version 1.2.0"

git push origin develop
```

---

# Правила проекта

✅ В `main` находятся только стабильные версии.

✅ Разработка ведётся только в `develop`.

✅ Каждый релиз сопровождается обновлением документации.

✅ Каждый релиз получает Git Tag.

✅ После релиза сразу начинается разработка следующей версии.

---
