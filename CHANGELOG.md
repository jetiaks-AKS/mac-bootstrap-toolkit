# Changelog

Все значимые изменения проекта **Mac Bootstrap Toolkit** документируются
в этом файле.

Формат основан на принципах **Keep a Changelog**.

## [Unreleased]

Текущая ветка разработки после релиза **2.0.0 Stable**.

### Added

#### Logging

- Добавлена поддержка отдельных history-log файлов для каждого режима Toolkit.
- Логи теперь автоматически получают префикс в зависимости от режима:
  - `bootstrap-YYYY-MM-DD_HH-MM-SS.log`
  - `check-YYYY-MM-DD_HH-MM-SS.log`
  - `discover-YYYY-MM-DD_HH-MM-SS.log`
- Добавлен единый `logs/latest.log` с последним выполненным запуском Toolkit.
- Добавлена временная метка к каждой записи лог-файла.
- Добавлена обработка прерывания Toolkit через `INT` и `TERM`.
- При прерывании Toolkit лог корректно завершается со статусом `Interrupted`.
- Добавлена защита от повторного закрытия Logger.

#### Module Lifecycle Logging

- Добавлено журналирование начала выполнения каждого модуля.
- Добавлено журналирование результата выполнения каждого модуля.
- Добавлено журналирование состояния `MODULE_CHANGED`.
- Добавлена фиксация результатов:
  - `SUCCESS`
  - `WARNING`
  - `ERROR`
  - `UNKNOWN`
- Добавлено аналогичное журналирование для конфигурационных модулей.

#### Configuration

- Добавлена политика исключения `config/generated/` из Git.
- Generated Configuration теперь рассматривается как machine-specific configuration.
- Generated Configuration продолжает использоваться локально для Discovery → Bootstrap, но не должна попадать в публичный репозиторий.

### Changed

#### Logging

- Logger теперь инициализируется до выполнения первого информационного сообщения Toolkit.
- Mode определяется централизованно для всех поддерживаемых режимов:
  - `Check`
  - `Bootstrap`
  - `Discovery`
- Улучшено разделение Compact и Verbose Output.
- Детальный вывод по-прежнему контролируется через `detail()`.
- Завершение Logger централизовано через `close_logger()`.
- Summary и финальные параметры выполнения записываются в history-log и `latest.log`.

#### Module Lifecycle

- `run_module()` теперь централизованно отвечает за:
  - запуск модуля;
  - подсчёт проверенных модулей;
  - определение изменения состояния;
  - подсчёт Installed / Skipped;
  - обработку Warning / Error;
  - журналирование результата.
- `run_configuration()` приведён к тому же принципу жизненного цикла модулей.
- Логирование Module Lifecycle больше не зависит от конкретного модуля.

#### Configuration

- Локальные machine-specific Generated Configuration больше не является частью публичного Git-состояния проекта.
- Конфигурация Git очищена от персональных значений пользователя:
  - `GIT_USER_NAME`
  - `GIT_USER_EMAIL`
- Публичная версия `config/git.conf` больше не содержит персональные Git identity settings.

* Summary адаптирован под режим выполнения Toolkit.

  Discovery, Bootstrap или Check.
